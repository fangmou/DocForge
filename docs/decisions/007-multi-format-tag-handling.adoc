= F8 多格式标签系统 — 实现决策记录

== 背景

标签系统原先仅支持 AsciiDoc 的 `:keywords:` 属性，Markdown 文件无标签能力。需要为 Markdown 添加标签支持，同时确保未来新增格式（如 Typst）时只需添加一个 impl 块。

== 方案

引入 `DocumentFormat` trait 抽象，每种格式实现标签/标题/大纲的提取和写入：

[source,rust]
----
pub trait DocumentFormat {
    fn extract_tags(&self, content: &str) -> Vec<String>;
    fn write_tag(&self, content: &str, tag: &str) -> String;
    fn remove_tag(&self, content: &str, tag: &str) -> String;
    fn extract_title(&self, content: &str) -> Option<String>;
    fn extract_headings(&self, content: &str) -> Vec<HeadingEntry>;
}
----

=== 格式对照

[cols="1,1,2,2"]
|===
| 格式 | 扩展名 | 标签语法 | 标题/大纲语法

| AsciiDoc | .adoc/.asciidoc/.txt | `:keywords: tag1, tag2` | `= Title` / `== Section`
| Markdown | .md/.markdown | YAML Front Matter `tags: [tag1, tag2]` | `# Title` / `## Section`
|===

=== 文件

|===
| 层级 | 文件 | 变更

| Rust 服务层 | `services/document_format.rs` | **新增** — trait 定义 + AsciidocFormat + MarkdownFormat + detect_format 工厂 + Front Matter 统一解析
| Rust 服务层 | `services/link_db.rs` | 重构 — parse_file / add/remove_tag_to_content 委托给 trait，collect_adoc_files 增加 .md/.markdown，RE_BLOCK_DELIM 改为导入
| Rust 命令层 | `commands/link.rs` | add_tag_to_file 传入 file_path + 新增 remove_tag_from_file
| 前端组件 | `components/tags-panel.js` | 标签删除统一走 IPC（removeTagFromFile）
| 前端组件 | `components/status-bar.js` | 标签计数改用 IPC 异步加载（getTagsForFile）
| 前端服务 | `services/link-index.js` | getTitle 回退正则增加 md/markdown + 新增 removeTagFromFile
|===

=== 扩展性

新增格式只需：

. 在 `document_format.rs` 中 `struct XxxFormat;` + `impl DocumentFormat for XxxFormat { ... }`
. `detect_format` 加一行 match
. `collect_adoc_files` 加对应扩展名

无需修改任何已有格式代码。

== 踩坑

=== 1. HeadingEntry 双定义

trait 的 `extract_headings` 返回 `Vec<HeadingEntry>`，但 `HeadingEntry` 原定义在 `link_db.rs` 中且带 `#[derive(Serialize)]`。

**方案**: 将 `HeadingEntry` 定义移到 `document_format.rs`（trait 所在文件），`link_db.rs` 通过 `pub use` 重导出，保持命令层的 `link_db::HeadingEntry` 引用不变。

=== 2. YAML Front Matter 解析不要引入 YAML 库

只需解析 `tags:` 一行，手写按行解析即可。支持两种格式：

- 内联数组: `tags: [tag1, tag2]`
- 多行列表: `tags:\n  - tag1\n  - tag2`

写入时统一转为内联数组格式，简化逻辑。

=== 3. 标签操作统一走后端 IPC

**问题**: 初始实现中，添加标签走后端 IPC（`add_tag_to_file`），删除标签却在前端用 JavaScript 重新实现（`_removeTagFromContent`/`_removeTagFromMarkdown`）。两端逻辑需保持同步，否则行为不一致。

**方案**: 新增 `remove_tag_from_file` IPC 命令，前端标签删除统一走后端。同时 status-bar 的标签计数改用 `getTagsForFile` IPC 异步加载，消除前端重复解析 front matter 的逻辑。

=== 4. Front Matter 解析去重

**问题**: `MarkdownFormat` 的 `parse_front_matter_tags`、`write_tag`、`remove_tag` 三处各自内联解析 front matter，`---` 检测和 tags 解析逻辑重复 3 次。

**方案**: 提取 `parse_front_matter()` 返回结构化的 `FrontMatter { end_idx, tags, other_lines }`，`write_tag` 和 `remove_tag` 基于该结构操作。同时提取 `unquote()` 和 `parse_inline_array()` 辅助方法消除重复的去引号和数组解析逻辑。

`extract_title` 和 `extract_headings` 的 front matter 跳过也统一使用 `skip_front_matter()` 行级检测（与 `parse_front_matter` 一致），避免 `starts_with("---\n")` 不精确匹配。
