== 导出配置树

导出配置采用树状结构，支持多源格式（AsciiDoc、未来 Markdown）和多导出格式（HTML、PDF、Word）。

[source,rust]
----
pub struct ExportConfig {
    pub output_dir: String,          // 通用输出目录（HTML/PDF/Word 共用）
    pub output_naming: String,       // 通用文件名规则 "stem" | "title"
    pub pandoc: PandocConfig,        // 全局 pandoc 工具（asciidoc→docx 和 markdown→docx 共用）
    pub asciidoc: AsciidocExportConfig, // AsciiDoc 专用配置
}

pub struct PandocConfig {
    pub command_path: String,        // pandoc 命令路径，默认 "pandoc"
    pub command_resolved: String,    // 缓存的解析路径（修改 command_path 时自动清空）
}

pub struct AsciidocExportConfig {
    pub enable_diagram: bool,        // 启用 asciidoctor-diagram，默认 false
    pub extra_args: String,          // 额外 CLI 参数（HTML 和 PDF 共用）
    pub pdf: PdfConfig,              // PDF 独有配置
    pub docx: DocxConfig,            // Word 独有配置
}

pub struct PdfConfig {
    pub command_path: String,        // asciidoctor-pdf 命令路径
    pub command_resolved: String,    // 缓存的解析路径
    pub theme: String,               // PDF 主题文件
    pub page_size: String,           // 页面大小，默认 "A4"
    pub fonts_dir: String,           // 字体目录
    pub footer_center: String,       // 页脚居中文本
    pub cover_image: String,         // 封面图片
    pub title_logo_image: String,    // 标题页 logo
    pub page_foreground_image: String, // 水印图片
}

pub struct DocxConfig {
    pub reference_doc: String,       // 参考 .docx 模板文件
}
----

*关键设计*:
- `pandoc` 位于 `ExportConfig` 顶层 — 因为 asciidoc→docx 和未来的 markdown→docx 共用
- `asciidoc.pdf.command_path` 保留 — asciidoctor-pdf 是 asciidoc 专有工具
- `asciidoc.docx` 不含 `command_path` — 用全局 `export.pandoc`
- `output_dir`/`output_naming`/`enable_diagram`/`extra_args` 是所有格式共用的通用配置

*设置 UI 导航*:

```
导出
  ├─ 通用          ← output_dir, output_naming, pandoc 路径 + 检测
  ├─ AsciiDoc · 引擎 ← enable_diagram, extra_args
  ├─ AsciiDoc · PDF ← asciidoctor-pdf 路径 + PDF 独有字段
  └─ AsciiDoc · Word ← reference_doc
```

== 工作区会话状态

每个工作区的会话状态（打开的标签页、最近文件、导出历史）存储在独立文件中，切换工作区时自动保存和恢复。

存储路径：`{app_config_dir}/workspaces/{hash}.json`，其中 `hash` 为工作区路径的 HashMap 默认哈希值（16 位十六进制）。

Draft 文件目录：`{app_config_dir}/workspace-drafts/{hash}/`，用于存储未保存文件内容和新建未保存的临时文件。文件正式保存后自动清理对应 draft。

WorkspaceState 结构：

[source,rust]
----
pub struct WorkspaceState {
    pub tabs: Vec<TabState>,
    pub active_file_path: String,
    pub recent_files: Vec<RecentFile>,
    pub export_history: Vec<ExportRecord>,
}

pub struct TabState {
    pub path: String,         // 文件路径或 __untitled_xxx
    pub scroll_top: u32,      // 滚动位置
    pub cursor_pos: u32,      // 光标位置
    pub is_dirty: bool,       // 是否有未保存修改
    pub draft_path: String,   // 未保存内容的 draft 文件路径，空串=无
}
----

*设计要点*:
- 已保存到磁盘的文件：TabState 只存路径和光标位置，内容从磁盘读取
- `__untitled_*` 或 `is_dirty=true` 的标签页：前端将内容写入 draft 文件，TabState 中记录 `draft_path`
- 切换工作区时：前端写 draft → Rust 保存状态文件 → 清空内存 → 加载新工作区 → 从磁盘/draft 恢复
- 文件正式保存后：前端删除对应 draft 文件
- 前端防抖自动保存（2 秒间隔），确保窗口意外关闭时数据不丢失
- `load_workspace_state` 时自动过滤掉磁盘文件已删除的标签页

*参数*: `workspace_path: String, state: WorkspaceState`（使用 AppHandle）
*返回*: `Result<(), String>`

保存工作区会话状态到独立 JSON 文件。同时清理该工作区 draft 目录中无用的 draft 文件（不在当前 tabs 的 draft_path 列表中的文件）。

返回指定工作区的 draft 目录路径（自动创建目录）。前端使用此路径直接读写 draft 文件（通过 `write_file`/`read_file` IPC 命令）。路径已标准化为 `/` 分隔符。
